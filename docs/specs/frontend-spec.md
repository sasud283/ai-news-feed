# AI News Feed

Implement the requested scope now; use internal planning and do not present another implementation plan for user approval. Enable Lovable Cloud for the database schema and auth.

User specification:
Build the frontend for an AI news aggregator site. This app only needs to read and display data from a Supabase database — it does not need to fetch, scrape, or classify any news content itself; that happens in a separate backend service that will write into the same database.

Data model (create these tables in Supabase with appropriate seed data for initial testing):
- stories: id, headline, ai_generated_summary (text), published_at, updated_at, is_correction_of (nullable, links to another story id for follow-ups)
- story_topics: story_id, topic (one of: Models & Research, Business & Funding, Policy & Regulation, National Initiatives, Ethics, Future of Work, Future of Daily Life, AI Equity & Representation, Tools & Products) — a story can have multiple topics
- story_tags: story_id, tone (Good / Useful / Bad / Ugly), access (Free / Paid), geography (Worldwide / US / China / Europe / Africa / Latin America / South & Southeast Asia / Middle East)
- story_sources: story_id, source_name, source_url, is_paywalled (boolean)
- spot_check_queue: story_id, reason, status (pending / approved / corrected), reviewed_at
- digest_subscribers: email, consented_at, filter_preferences (json), unsubscribed (boolean)

Pages and features to build:
1. Home feed — a reverse-chronological list of stories, one card per story (not one per source). Each story card shows:
   - headline
   - AI-generated summary
   - topic tag(s)
   - tone tag
   - geography tag
   - access indicator (free/paid)
   - list of contributing sources as clickable links
   - visible "Summary generated by AI" label
   - "report an issue" link
   - if applicable, a link to a follow-up/correction story
2. Filter bar — combinable filters for Topic (multi-select), Tone, Access, Geography.
   - Filters shareable via URL (URL query params for shareable filtered views)
   - Signed-in readers can save a filter combination as their personal default
3. Search — free-text search box across headlines and summaries.
4. Digest sign-up — email capture form tied to the current filter combination, with an explicit (unchecked) consent checkbox and link to privacy policy. Store consent timestamp.
5. Spot-check review page (admin only, simple auth):
   - Shows stories in spot_check_queue with proposed tags, AI summary
   - One-click approve or correct-and-approve actions
   - Correction allows editing topic/tone/access/geography tags and summary text before approving
6. Privacy policy page & "About / How this works" page explaining AI-generated content and filtering.

Design direction: Clean, editorial, readable — closer to a serious news site than a flashy dashboard. Responsive and polished on mobile. Visually distinct filter tags (e.g., color-coded tone badges) for quick feed scanning.

Scope boundaries: Do not build scraping, RSS ingestion, deduplication, or classification logic. Focus entirely on the database schema, feed reading, filtering, digest signups, and spot-check queue reviews.
